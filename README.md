# Ветеринарная клиника

Консольное C++-приложение для управления работой ветеринарной клиники. Программа позволяет вести список животных и ветеринаров, оформлять обращения и просматривать историю приёмов. При создании обращения проверяется, может ли врач выбранной специализации принять данное животное.

## Возможности приложения

- добавление животных (собака, кошка, птица, грызун) и ветеринаров;
- просмотр списка зарегистрированных животных (отсортирован по возрасту);
- просмотр списка ветеринаров и их специализаций;
- запись животного на приём с указанием даты, диагноза и назначенного лечения;
- просмотр истории обращений;
- удаление животных (по кличке и владельцу) и ветеринаров (по имени);
- проверка наличия врача и животного при оформлении обращения;
- проверка того, что врач данной специализации может лечить это животное.

При запуске программа заполняет клинику демонстрационными данными (3 ветеринара, 4 животных, 3 обращения), выводит в консоль таблицу с результатами полиморфных вызовов (тип, звук, стоимость осмотра, рекомендации по уходу для животных разных типов), после чего открывает меню. Данные хранятся только в памяти во время работы; сохранение в файл не реализовано.

## Предметная область

- **Животное (`Animal`)** — кличка, порода, возраст, владелец. Абстрактный базовый класс иерархии: создать объект `Animal` напрямую нельзя, только объекты его наследников.
- **Ветеринар (`Vet`)** — имя и специализация.
- **Обращение (`Appeals`)** — ветеринар, животное (`std::shared_ptr<Animal>`), дата, диагноз и лечение.
- **Клиника (`VetClinic`)** — хранит `std::vector` животных, ветеринаров и обращений и управляет ими.

## Запуск приложения

### Требования

- Windows (в `main.cpp` используется `<Windows.h>` для включения UTF-8 в консоли);
- Visual Studio 2019 версии 16.10 или новее с поддержкой разработки на C++;
- стандарт языка **C++20** (нужен для оператора `<=>` и заголовка `<format>`).

### Сборка

1. Скачайте или клонируйте репозиторий.
2. Создайте в Visual Studio проект **Console App** и добавьте в него все `.h` и `.cpp` файлы. Заголовки подключаются как `../headers/...`, поэтому сохраните структуру каталогов (см. ниже).
3. В свойствах проекта установите стандарт **ISO C++20** или новее.
4. Соберите и запустите программу.

### Меню

| Пункт | Действие                   |
|------:|----------------------------|
| `1`   | Добавить ветеринара        |
| `2`   | Добавить животное          |
| `3`   | Записать животное на приём |
| `4`   | Показать всех ветеринаров  |
| `5`   | Показать всех животных     |
| `6`   | Показать историю обращений |
| `7`   | Удалить ветеринара         |
| `8`   | Удалить животное           |
| `0`   | Выйти                      |

Ввод данных построчный (каждое поле с новой строки). При добавлении животного сначала выбирается тип (собака / кошка / птица / грызун), после чего программа показывает подсказку, какие поля нужно ввести. При записи на приём врач ищется по специализации (берётся первый подходящий), животное — по кличке.

## Лабораторная работа №2: дружественные функции и перегрузка операторов

**Тема:** Дружественные функции, перегрузка функций и операторов. **Вариант:** 8 — «Ветеринарная клиника».

### Цель работы

Расширить систему, разработанную в предыдущей лабораторной работе, используя дружественные функции и перегрузку операторов: реализовать сравнение объектов, ввод и вывод данных, добавление и удаление связанных объектов, а также обработку ситуаций, когда операция невозможна.

### Реализация

#### `Animal`

- `operator==` — животные равны, если совпадают кличка и владелец;
- `operator<=>` — сравнение по возрасту (`std::strong_ordering`); благодаря ему работают `<`, `>`, `<=`, `>=`, и по нему список животных в клинике сортируется при добавлении;
- `operator<<` / `operator>>` — дружественные функции, которые вызывают виртуальные методы `print` / `read`.

#### `Vet`

- `operator==` — сравнение по имени;
- `operator<<` / `operator>>` — дружественные функции вывода и ввода (имя и специализация, каждое с новой строки).

#### `Appeals`

Хранит врача, животное, дату, диагноз и лечение. Дружественный `operator<<` выводит специализацию и имя врача, тип и кличку животного, дату, диагноз и лечение.

#### `VetClinic`

- `operator+=` — добавляет животное (`std::shared_ptr<Animal>`) или ветеринара;
- `operator-=` — удаляет животное (поиск по `==`, т. е. по кличке и владельцу) или ветеринара (по имени). Если объект не найден, выводится сообщение;
- `removeAnimal(name, owner)` — удаляет животное по кличке и владельцу без создания временного объекта (используется в меню, так как `Animal` теперь абстрактный);
- `setAppeals` возвращает `false` и сообщает причину, если врач или животное не найдены либо врач не может лечить это животное.

## Лабораторная работа №3: наследование

**Тема:** Наследование классов. **Вариант:** 8 — «Ветеринарная клиника».

### Иерархия классов

```
Animal  (абстрактный)
├── Dog     — walksPerDay: количество прогулок в день
├── Cat     — hairballsPerMonth: количество волосяных комков в месяц
├── Bird    — wingspan: размах крыльев (см)
└── Rodent  — incisorLength: длина резцов (мм)
```

`Animal` — абстрактный базовый класс (кличка, порода, возраст, владелец). Конструктор базового класса защищённый: он вызывается только из конструкторов наследников. Тип животного определяется самим классом и возвращается виртуальным методом `getType()`.

### Правила допуска врачей

Метод `canBeTreatedBy` работает как «чёрный список»: он перечисляет специализации, которые лечить это животное **не могут**.

| Тип животного   | Не может лечить врач         |
|-----------------|------------------------------|
| `Dog`, `Cat` (общая логика из `Animal`) | Ornithologist, Rodentologist |
| `Bird`          | Therapist, Rodentologist     |
| `Rodent`        | Therapist, Ornithologist     |

### Специфические методы производных классов

Этих методов нет в базовом классе, поэтому они вызываются только у объектов производных типов. Формулы упрощённые, приведены для демонстрации. Результат этих методов используется внутри `checkupPrice()` (см. лабораторную работу №4).

| Класс    | Метод                   | Что считает                                                                          |
|----------|-------------------------|--------------------------------------------------------------------------------------|
| `Dog`    | `weeklyWalkHours()`     | часы прогулок в неделю (одна прогулка = 30 минут): `walksPerDay * 30 * 7 / 60`       |
| `Cat`    | `groomingsPerWeek()`    | сколько раз в неделю нужно вычёсывать кошку: `min(7, 1 + hairballsPerMonth / 2)`     |
| `Bird`   | `minCageWidth()`        | минимальная ширина клетки, см: `wingspan * 2`                                        |
| `Rodent` | `daysUntilDentalTrim()` | дней до подрезания резцов: `(35 - incisorLength) / 0.275`, 0 если длина больше 35 мм |

Дополнительно `Bird::careAdvice()` добавляет совет про просторный вольер, если размах крыльев больше 50 см, а `Cat::careAdvice()` подставляет в совет число вычёсываний в неделю.

### Что изменилось в остальных классах

- `VetClinic` и `Appeals` хранят животных как `std::shared_ptr<Animal>`, чтобы не терять данные потомков.
- Проверка «врач подходит животному» (`appointmentCheck`) делегируется самому животному через `canBeTreatedBy`.
- В меню при добавлении животного сначала выбирается тип, а подсказка по вводу берётся из `inputHint()`.

## Лабораторная работа №4: полиморфизм и абстрактные классы

**Тема:** Полиморфизм, виртуальные функции, абстрактные классы.

### Цель работы

Продолжить разработку иерархии классов из предыдущей лабораторной работы и реализовать полиморфное взаимодействие с объектами различных производных типов: сделать базовый класс абстрактным, добавить чисто виртуальные методы и продемонстрировать динамический полиморфизм через указатели на базовый класс.

### Абстрактный базовый класс

`Animal` содержит три **чисто виртуальных** метода, поэтому экземпляр `Animal` создать нельзя (`Animal a;` не компилируется). Каждый наследник обязан их реализовать.

Деструктор базового класса **виртуальный**, поэтому объекты-наследники, удаляемые через `std::shared_ptr<Animal>`, уничтожаются корректно.

### Виртуальные методы

| Метод                        | Вид                       | Роль                                              | Что делает                                                                                   | Переопределяют                 |
|------------------------------|---------------------------|---------------------------------------------------|----------------------------------------------------------------------------------------------|--------------------------------|
| `getType()`                  | чисто виртуальный         | получение типа объекта                            | возвращает название типа: `"Dog"`, `"Cat"`, `"Bird"`, `"Rodent"`                             | `Dog`, `Cat`, `Bird`, `Rodent` |
| `checkupPrice()`             | чисто виртуальный         | **специфическое вычисление**                      | стоимость планового осмотра, зависит от фактического типа и полей объекта                    | `Dog`, `Cat`, `Bird`, `Rodent` |
| `makeSound()`                | чисто виртуальный         | специфическое действие                            | звук животного                                                                               | `Dog`, `Cat`, `Bird`, `Rodent` |
| `print(os)`                  | виртуальный               | вывод информации                                  | вывод полей (потомок вызывает `Animal::print` и добавляет свои поля)                         | `Dog`, `Cat`, `Bird`, `Rodent` |
| `read(is)`                   | виртуальный               | ввод информации                                   | ввод полей (аналогично `print`)                                                              | `Dog`, `Cat`, `Bird`, `Rodent` |
| `careAdvice()`               | виртуальный с реализацией | рекомендации по уходу                             | базовая фраза + дополнение потомка                                                           | `Dog`, `Cat`, `Bird`, `Rodent` |
| `canBeTreatedBy(speciality)` | виртуальный с реализацией | допуск врача                                      | может ли врач данной специализации принять животное                                          | `Bird`, `Rodent`               |
| `inputHint()`                | виртуальный с реализацией | подсказка для меню                                | какие поля нужно ввести                                                                      | `Dog`, `Cat`, `Bird`, `Rodent` |

Чисто виртуальными сделаны методы, для которых у «просто животного» нет осмысленной общей реализации (тип, звук и цена осмотра зависят от вида). Методы, у которых есть общее поведение (`print`, `careAdvice`, `canBeTreatedBy`), имеют реализацию в базе, а наследники её дополняют или заменяют.

### Специфическое полиморфное действие: стоимость осмотра

`checkupPrice()` вызывается одинаково для любого животного, а результат зависит от фактического типа объекта. Базовая цена — 67, далее надбавки по характеристикам вида (в расчёте используются специфические методы из лабораторной работы №3):

| Класс    | Формула                                                       | Что учитывается                                       |
|----------|---------------------------------------------------------------|-------------------------------------------------------|
| `Dog`    | `67 + weeklyWalkHours() * 2 + (возраст > 8 ? 15 : 0)`         | нагрузка от прогулок, пожилой возраст                 |
| `Cat`    | `67 + groomingsPerWeek() * 4`                                 | частота вычёсывания (зависит от комков шерсти)        |
| `Bird`   | `67 + wingspan * 0.5 + (wingspan > 50 ? 25 : 0)`              | размер птицы, доплата за крупных                      |
| `Rodent` | `67 + (daysUntilDentalTrim() == 0 ? 20 : 0)`                  | доплата, если нужна срочная чистка резцов             |

### Коллекции указателей на базовый класс

- `VetClinic::animal` — `std::vector<std::shared_ptr<Animal>>`: в ней одновременно лежат собаки, кошки, птицы и грызуны. Метод `infoAnimal()` выводит их через `operator<<`, который вызывает виртуальный `print()`.
- В `main.cpp` создаётся отдельный `std::vector<std::shared_ptr<Animal>> pets` с объектами всех четырёх производных типов. В цикле через указатель на базовый класс вызываются `getType()`, `makeSound()`, `checkupPrice()` и `careAdvice()`: код вызова один и тот же, а результат зависит от фактического типа объекта.

Пример вывода демонстрационной части:

```
Dog Sharik: Woof! | 87 | Routine checkup once a year. Need to take out for a walk.
Bird Gosha: Tweet! | 137 | Routine checkup once a year. A large bird needs a spacious aviary.
Cat Barsik: Meow! | 79 | Routine checkup once a year. Brush the cat 3 times a week.
Rodent Homa: Squeak! | 67 | Routine checkup once a year. Monitor the condition and length of the teeth.
```

### Управление временем жизни объектов

Все объекты создаются через `std::make_shared`, ручных `new` и `delete` в программе нет. Используется `std::shared_ptr`, а не `std::unique_ptr`, потому что одно и то же животное одновременно принадлежит клинике и записи об обращении (`Appeals`): после удаления животного из клиники запись в истории остаётся корректной, а объект уничтожается, когда на него не остаётся ссылок. Благодаря виртуальному деструктору вызывается деструктор фактического типа.

### Динамический полиморфизм в программе

- `VetClinic::appointmentCheck` принимает `const Animal&` и вызывает `canBeTreatedBy`: выполняется версия того класса, к которому принадлежит животное (у `Bird` и `Rodent` своя, у `Dog` и `Cat` — из `Animal`);
- `Animal::print` вызывает виртуальный `getType()`, поэтому тип выводится правильно для любого наследника;
- `operator<<` и `operator>>` вызывают виртуальные `print` и `read`;
- меню создаёт объект нужного типа и дальше работает с ним только через `std::shared_ptr<Animal>` (в том числе вызывает `inputHint()` и ввод через `>>`).
