# Ветеринарная клиника

Консольное приложение на C++ для управления ветеринарной клиникой. Оно позволяет регистрировать животных и ветеринаров, оформлять обращения, просматривать историю приёмов и проверять, подходит ли специализация врача для выбранного животного.

Приложение демонстрирует объектно-ориентированное программирование на C++: наследование, полиморфизм, абстрактные классы, перегрузку операторов, шаблоны, обработку исключений и файловый ввод-вывод.

## Возможности

- добавление ветеринаров с указанием имени и специализации;
- добавление собак, кошек, птиц и грызунов с индивидуальными характеристиками;
- просмотр списка ветеринаров и зарегистрированных животных;
- автоматическая сортировка животных по возрасту при добавлении;
- оформление обращения с указанием врача, животного, даты, диагноза и лечения;
- проверка наличия врача и животного, а также совместимости специализации врача с видом животного;
- просмотр истории обращений;
- удаление ветеринаров и животных;
- проверка введённых данных и обработка ошибок;
- сохранение состояния клиники в файл и его загрузка при следующем запуске;
- журнал событий с датой и временем (запись всегда дописывается в конец файла);
- формирование текстового отчёта по данным клиники.

При запуске программа загружает сохранённое состояние из файла `clinic.txt`: ветеринаров, животных и обращения. Если файла ещё нет (первый запуск), клиника начинает работу пустой. После этого открывается основное меню. При выходе из программы состояние записывается обратно в тот же файл. Подробнее об этом в описании лабораторной работы №7.

## Предметная область

| Сущность | Назначение |
|---|---|
| `Animal` | Абстрактный базовый класс животного. Содержит кличку, породу, возраст и имя владельца. |
| `Dog`, `Cat`, `Bird`, `Rodent` | Производные классы с характеристиками и поведением, специфичными для вида животного. |
| `Vet` | Ветеринар: имя и специализация. |
| `Appeals` | Обращение: ветеринар, животное, дата, диагноз и назначенное лечение. |
| `VetClinic` | Управляет коллекциями животных, ветеринаров и обращений. |
| `Collection<T>` | Универсальный шаблонный контейнер, используемый для хранения данных клиники. |

### Иерархия животных

```text
Animal (абстрактный базовый класс)
├── Dog     — количество прогулок в день
├── Cat     — количество волосяных комков в месяц
├── Bird    — размах крыльев
└── Rodent   — длина резцов
```

Каждый производный класс реализует собственные методы получения типа, звука и стоимости осмотра, а также ввода и вывода характеристик.

## Запуск приложения

### Требования

- операционная система Windows;
- Visual Studio 2022 с компонентом разработки классических приложений на C++;
- поддержка стандарта **C++20**, включая `<format>`, `<ranges>`, `<filesystem>` и `<chrono>` (часовые пояса).

Пути к файлам по умолчанию заданы в `sources/main.cpp` для Windows (диск `D:`). Каталог `D:/Veterinary-Clinic` должен существовать: программа создаёт файлы, но не каталоги. При необходимости пути можно изменить.

### Сборка в Visual Studio

В архиве находятся исходные файлы, но нет готового файла решения Visual Studio (`.sln`) или проекта (`.vcxproj`). Для сборки:

1. Распакуйте архив, не меняя расположение каталогов `headers`, `sources` и `exception`.
2. Создайте в Visual Studio проект **Console App (C++)**.
3. Добавьте в проект все `.cpp`-файлы из каталога `sources`.
4. Убедитесь, что каталоги `headers` и `exception` находятся на прежних местах относительно `sources`: исходные файлы подключают заголовки через относительные пути.
5. В свойствах проекта выберите стандарт языка **ISO C++20** (`/std:c++20`).
6. Соберите и запустите проект.

### Главное меню

| Пункт | Действие |
|---:|---|
| `1` | Add a veterinarian — добавить ветеринара |
| `2` | Add an animal — добавить животное |
| `3` | Schedule an appointment — оформить обращение |
| `4` | Show all doctors — показать ветеринаров |
| `5` | Show all animals — показать животных |
| `6` | Show appointment history — показать историю обращений |
| `7` | Remove veterinarian — удалить ветеринара |
| `8` | Remove the animal — удалить животное |
| `9` | Create a report — сформировать текстовый отчёт |

Ввод выполняется построчно. При добавлении животного сначала нужно выбрать его тип. Затем программа показывает подсказку с перечнем общих и дополнительных полей. При оформлении обращения врач выбирается по полному имени, а животное — по кличке и имени владельца, поэтому связь с объектами определяется однозначно.

Для удаления ветеринара вводится его полное имя. Для удаления животного нужно указать кличку и имя владельца.

## Реализованные темы лабораторных работ

### Лабораторная работа №2. Дружественные функции и перегрузка операторов

**Вариант:** 8 — «Ветеринарная клиника».

В проекте реализованы перегрузки операторов для сравнения, ввода и вывода объектов, а также для добавления и удаления элементов клиники.

**Класс `Animal`:**

- `operator==` сравнивает животных по кличке и имени владельца;
- `operator<=>` сравнивает животных по возрасту. На его основе доступны операторы сравнения, а клиника сортирует животных при добавлении;
- `operator<<` и `operator>>` вызывают виртуальные методы `print()` и `read()`, поэтому корректно работают с объектами производных классов;
- отдельная перегрузка `operator<<` позволяет выводить `std::shared_ptr<Animal>` как данные животного, а не как адрес.

**Класс `Vet`:**

- `operator==` сравнивает ветеринаров по имени;
- `operator<<` и `operator>>` обеспечивают вывод и ввод имени и специализации.

**Класс `Appeals`:** дружественный `operator<<` выводит информацию о ветеринаре, животном, дате, диагнозе и лечении.

**Класс `VetClinic`:**

- `operator+=` добавляет животное или ветеринара;
- `operator-=` удаляет животное или ветеринара;
- `removeAnimal(name, owner)` позволяет удалить животное по кличке и владельцу без создания объекта абстрактного класса `Animal`.

Если объект для удаления не найден, генерируется `NotFoundException`. При добавлении проверяется наличие дубликатов.

### Лабораторная работа №3. Наследование

`Animal` выступает базовым классом, от которого наследуются `Dog`, `Cat`, `Bird` и `Rodent`. Общие характеристики (кличка, порода, возраст и владелец) хранятся в базовом классе, а дополнительные параметры — в производных.

| Класс | Дополнительное поле | Специфический метод |
|---|---|---|
| `Dog` | `walksPerDay` — прогулок в день | `weeklyWalkHours()` — расчёт часов прогулок в неделю |
| `Cat` | `hairballsPerMonth` — волосяных комков в месяц | `groomingsPerWeek()` — расчёт рекомендуемой частоты вычёсывания |
| `Bird` | `wingspan` — размах крыльев | `minCageWidth()` — расчёт минимальной ширины клетки |
| `Rodent` | `incisorLength` — длина резцов | `daysUntilDentalTrim()` — оценка количества дней до подрезания резцов |

Метод `canBeTreatedBy()` определяет, может ли врач выбранной специализации лечить животное. В базовом классе запрещены специализации `Ornithologist` и `Rodentologist`; `Bird` и `Rodent` переопределяют это правило:

| Тип животного | Специализации, которым запрещён приём |
|---|---|
| `Dog`, `Cat` | `Ornithologist`, `Rodentologist` |
| `Bird` | `Therapist`, `Rodentologist` |
| `Rodent` | `Therapist`, `Ornithologist` |

### Лабораторная работа №4. Полиморфизм и абстрактные классы

`Animal` является абстрактным классом: у него есть три чисто виртуальных метода, которые должны быть реализованы в каждом производном классе:

- `getType()` — возвращает тип животного;
- `checkupPrice()` — рассчитывает стоимость осмотра;
- `makeSound()` — возвращает характерный звук.

Также в базовом классе определены виртуальные методы `careAdvice()`, `canBeTreatedBy()`, `print()`, `read()` и `inputHint()`. Производные классы переопределяют их, когда требуется поведение, зависящее от вида животного.

Полиморфизм используется, например, при хранении разных видов животных в одной коллекции `Collection<std::shared_ptr<Animal>>`: вызов виртуального метода через указатель на базовый класс приводит к выполнению реализации фактического типа объекта.

Стоимость осмотра рассчитывается по разным формулам в классах-наследниках. Это демонстрационная логика проекта, а не реальные ветеринарные тарифы.

| Класс | Расчёт стоимости осмотра |
|---|---|
| `Dog` | `67 + weeklyWalkHours() * 2 + (возраст > 8 ? 15 : 0)` |
| `Cat` | `67 + groomingsPerWeek() * 4` |
| `Bird` | `67 + wingspan * 0.5 + (wingspan > 50 ? 25 : 0)` |
| `Rodent` | `67 + (daysUntilDentalTrim() == 0 ? 20 : 0)` |

Для совместного владения животными используются `std::shared_ptr`. Один объект может одновременно храниться в клинике и в обращении. Поэтому удаление животного из списка клиники не уничтожает объект, пока на него ссылается запись в истории обращений.

### Лабораторная работа №5. Шаблоны и обобщённое программирование

#### Шаблонный класс `Collection<T>`

Класс находится в `headers/collection.h` и использует `std::vector<T>` для хранения элементов. Он не зависит от предметной области и предоставляет следующие операции:

| Метод или оператор | Назначение |
|---|---|
| `add(item)` | добавить элемент в конец коллекции |
| `removeIf(condition)` | удалить первый элемент, удовлетворяющий условию |
| `findIf(condition)` | найти первый подходящий элемент или вернуть `nullptr` |
| `operator[](index)` | получить элемент по индексу с проверкой границ |
| `size()` | получить количество элементов |
| `empty()` | проверить, пуста ли коллекция |
| `clear()` | удалить все элементы |
| `begin()` / `end()` | обеспечить перебор коллекции в цикле range-based `for` |
| `print(os)` | вывести элементы через `operator<<` |

Условия поиска и удаления передаются в виде предикатов, в том числе лямбда-выражений. При обращении по недопустимому индексу `operator[]` выбрасывает `OutOfRangeException`.

В `VetClinic` шаблон используется для трёх типов данных:

- `Collection<std::shared_ptr<Animal>>` — животные;
- `Collection<Vet>` — ветеринары;
- `Collection<Appeals>` — обращения.

#### Шаблонная функция `findAll`

Функция из `headers/findAll.h` перебирает `Collection<T>` и возвращает `std::vector<T>` со всеми элементами, удовлетворяющими переданному условию. В отличие от `findIf`, который возвращает первый найденный элемент, `findAll` собирает все совпадения. Это вспомогательная функция; текущий сценарий основного меню её не вызывает.

### Лабораторная работа №6. Обработка исключительных ситуаций

Для разделения разных ситуаций в проекте созданы собственные классы исключений в каталоге `exception/`. Они наследуются от разных классов стандартной иерархии `std::exception`:

| Исключение | Базовый класс | Для чего используется |
|---|---|---|
| `InputFormatException` | `std::runtime_error` | введено значение неподходящего формата, например текст вместо числа; также используется при разборе повреждённой строки файла |
| `InvalidDataException` | `std::invalid_argument` | данные не прошли проверку: пустое обязательное поле, символ-разделитель или значение вне допустимых ограничений |
| `DuplicateException` | `std::runtime_error` | попытка добавить уже зарегистрированное животное или ветеринара |
| `NotFoundException` | `std::runtime_error` | ветеринар или животное не найдены при поиске или удалении |
| `IncompatibleVetException` | `std::logic_error` | специализация ветеринара не подходит для выбранного животного |
| `OutOfRangeException` | `std::out_of_range` | обращение к элементу `Collection<T>` по недопустимому индексу |
| `FileException` | `std::runtime_error` | ошибка открытия, чтения или записи файла (добавлено в лабораторной работе №7) |

Ошибки перехватываются с помощью `try`/`catch` на нескольких уровнях:

- функции меню (`addAnimal`, `addVeterinarian`, `scheduleAppointment`, `removeAnimal`, `removeVeterinarian`) перехватывают конкретные типы исключений, выводят сообщение в консоль, записывают его в журнал и возвращают пользователя в меню;
- главный цикл в `main` перехватывает `InputFormatException`, а также любое другое `std::exception`, поэтому непредвиденная ошибка не завершает программу аварийно;
- методы `VetClinic::load`, `save`, `repEvent` и `logEvent` обрабатывают ошибки файловых операций, и сбой при работе с файлом (в том числе с журналом) не приводит к падению программы.

### Лабораторная работа №7. Потоки и файловый ввод-вывод

Состояние клиники сохраняется в файл и восстанавливается из него при следующем запуске. Дополнительно ведётся журнал событий и формируется текстовый отчёт. Используются стандартные файловые потоки `std::ifstream` и `std::ofstream`.

#### Компоненты

| Компонент | Назначение |
|---|---|
| `ClinicStorage` | Сохранение состояния клиники в файл (`save`) и загрузка из файла (`load`). Хранит путь к файлу. |
| `Logger` | Журнал событий: открывает файл в режиме дозаписи `std::ios::app` и добавляет строку с датой и временем. |
| `Report` | Формирование читаемого текстового отчёта по данным клиники. |
| `FileException` | Исключение для ошибок открытия, чтения и записи файлов. |
| `validation.h` | Функция `checkNoSeparator`: запрещает символ `#` в текстовых полях, так как он используется как разделитель в файле. |

`VetClinic` хранит указатели на `Logger`, `Report` и `ClinicStorage` и предоставляет методы `load()`, `save()`, `repEvent()` и `logEvent()`. Они вызывают соответствующие операции и обрабатывают их ошибки. Пути к файлам задаются в `sources/main.cpp`:

| Файл | Назначение | Режим открытия |
|---|---|---|
| `clinic.txt` | сохранённое состояние | перезапись |
| `clinicLog.log` | журнал событий | дозапись в конец |
| `report.txt` | текстовый отчёт | перезапись |

#### Формат файла состояния

Файл текстовый: одна запись на строку, поля разделены символом `#`, первым полем указан тип записи. Сначала записываются ветеринары, затем животные, затем обращения.

| Тип записи | Поля |
|---|---|
| `VET` | имя # специализация |
| `DOG` | кличка # порода # возраст # владелец # прогулок в день |
| `CAT` | кличка # порода # возраст # владелец # волосяных комков в месяц |
| `BIRD` | кличка # порода # возраст # владелец # размах крыльев |
| `RODENT` | кличка # порода # возраст # владелец # длина резцов |
| `APPEALS` | имя врача # кличка животного # владелец животного # дата # диагноз # лечение |

Пример:

```text
VET#Ivan Ivanov#Therapist
VET#Anna Petrova#Ornithologist
RODENT#Homa#Djungarian hamster#1#Dmitry#15.5
BIRD#Kesha#Budgerigar#2#Elena#20
DOG#Rex#German Shepherd#5#Maria#2
APPEALS#Ivan Ivanov#Rex#Maria#13.09.2026#Routine checkup#Vitamin course
```

Указатели в файл записать нельзя, поэтому связи между объектами хранятся через ключи: врач определяется по имени, животное по паре «кличка + владелец». Тип записи позволяет при загрузке создать объект нужного класса. Метод `save` реализован полиморфно: у `Animal` и наследников есть виртуальный метод `save(std::ostream&)`, который записывает общие поля и поле, специфичное для вида.

#### Загрузка и проверки

Файл читается построчно (`std::getline`). Каждая строка разбивается на поля, после чего создаётся объект нужного типа. Пустые строки пропускаются, а символ `\r` в конце строки (файл, сохранённый в другой системе) удаляется. Загрузка выполняется через те же методы, что и ручной ввод (`setVet`, `setAnimal`, `setAppeals` и сеттеры), поэтому проверки применяются автоматически:

| Что проверяется | Как |
|---|---|
| успешное открытие файла | `is_open()`, иначе `FileException` |
| ошибки чтения | `bad()` после чтения, иначе `FileException` |
| ошибки записи | проверка состояния потока после записи, иначе `FileException` |
| корректность данных | число полей в строке; числа разбираются с проверкой формата, знака и диапазона; пустые поля запрещены; неизвестный тип записи |
| ограничения предметной области | проверки в сеттерах (например, возраст и число прогулок ограничены), совместимость специализации врача с видом животного |
| уникальность | дубликаты ветеринаров и животных отвергаются (`DuplicateException`) |
| существование связанных объектов | врач и животное из обращения должны быть уже загружены (`NotFoundException`) |

Любая ошибка в строке превращается в `InputFormatException` с номером строки, например `Line 3: A Ornithologist cannot treat a Dog`. Если загрузка не удалась, клиника очищается, а при выходе из программы файл состояния не перезаписывается, чтобы не потерять исходные данные. Если файла нет (первый запуск), загрузка пропускается без ошибки.

#### Журнал

Каждая запись содержит дату, время, уровень и сообщение:

```text
[2026-11-28 14:05:32] INFO: Vet added: Therapist: Ivan Ivanov
[2026-11-28 14:06:10] ERROR: Not found: Animal 'Tom', owner 'Ann' not found
```

В журнал попадают запуск и завершение программы, добавление и удаление ветеринаров, животных и обращений, просмотр списков, сохранение, загрузка, формирование отчёта и все перехваченные ошибки. Журнал никогда не очищается: каждая запись дописывается в конец файла. Ошибка записи в журнал выводится в консоль, но работу программы не останавливает.

#### Отчёт

Пункт меню `9` создаёт файл `report.txt` с разделами: ветеринары, животные (тип, кличка, порода, возраст, владелец, стоимость осмотра), обращения и итоги (количество ветеринаров, животных по видам и обращений, суммарная стоимость осмотров). Отчёт предназначен для чтения человеком и обратно не загружается.
